> [!summary] 本节核心内容

## 🎯 各层封装细节详解

> [!info] 1. 应用层（HTTP层）
> - **任务**：构建HTTP请求报文
> - **内容示例**：
![](https://int-1330323257.cos.ap-guangzhou.myqcloud.com//obsidian/pic/202606080150807.png)
> - **作用**：定义Web应用通信的语义和语法

> [!important] 2. 运输层（TCP层）
> - **任务**：添加TCP首部，形成TCP报文段
> - **TCP首部作用**：
>   - **区分应用进程**：通过端口号标识浏览器进程和Web服务器进程
>   - **实现可靠传输**：序列号、确认号、窗口大小等字段
>     ![](https://int-1330323257.cos.ap-guangzhou.myqcloud.com//obsidian/pic/202606080151882.png)
> - **关键概念**：端到端的进程间可靠通信

> [!important] 3. 网络层（IP层）
> - **任务**：添加IP首部，形成IP数据报
> - **IP首部作用**：
>   - **网络间传输**：使数据报能在互联网上传送
>   - **路由器转发**：包含源IP和目的IP地址，供路由器查表转发
>   - **分片与重组**：处理不同网络的最大传输单元差异
>     ![](https://int-1330323257.cos.ap-guangzhou.myqcloud.com//obsidian/pic/202606080152494.png)
> - **路由器关键操作**：解析IP首部 → 提取目的网络地址 → 查找路由表 → 确定转发端口

> [!check] 4. 数据链路层（以太网层）
> - **任务**：添加帧首部和尾部，形成以太网帧
> - **帧首部作用**：
>   - **链路/网络内传输**：让帧能在一段链路或一个网络上传输
>   - **目的主机接收**：包含目的MAC地址，确保正确主机接收
> - **帧尾部作用**：
>   - **误码检测**：包含帧校验序列（FCS），让目的主机检查接收帧是否有误码
>- **图解**：
>  ![](https://int-1330323257.cos.ap-guangzhou.myqcloud.com//obsidian/pic/202606080153686.png)


> [!check] 5. 物理层
> - **任务**：
>   - 添加前导码到比特流
>   - 将比特流转换为信号发送到传输媒体
>     ![](https://int-1330323257.cos.ap-guangzhou.myqcloud.com//obsidian/pic/202606080154850.png)
> - **前导码作用**：
>   - **同步准备**：让目的主机做好接收帧的准备（时钟同步）
> - **注意**：物理层不关心数据内容，只处理比特传输


## 🔑 路由器关键角色分析
> [!warning] 路由器处理的特殊性质
> 路由器在转发过程中**只处理到网络层**，不会处理运输层和应用层内容：
> 
> **路由器处理流程**：
> ```
> 物理层 → 数据链路层 → 网络层 → 数据链路层 → 物理层
>         (解封装)      (路由决策)   (再封装)
> ```
> 
> **为什么只到网络层？**
> - **路由决策**：只需IP地址信息（网络层）
> - **性能考虑**：不解封装到更高层，转发速度更快
> - **职责分离**：路由器专注"分组转发"，主机处理"端到端通信"

### 📝 各层协议数据单元（PDU）总结

| 层次        | 协议数据单元（PDU）                          | 添加的头部/尾部      | 主要作用       |
| --------- | ------------------------------------ | ------------- | ---------- |
| **应用层**   | HTTP报文（Message）                      | 应用协议定义的头部     | 应用语义和数据    |
| **运输层**   | TCP报文段（Segment）<br>或 用户数据报（Datagram） | TCP首部 或 UDP首部 | 进程标识、可靠传输  |
| **网络层**   | IP数据报（Datagram）或 分组（Packet）          | IP首部          | 网络间路由、寻址   |
| **数据链路层** | 帧（Frame）                             | 帧首部 + 帧尾部     | 链路内传输、错误检测 |
| **物理层**   | 比特流（Bit Stream）                      | 前导码（物理层特有）    | 比特传输、信号编码  |

## 🎓 关键学习要点
> [!tip] 必须掌握的核心概念
> 1. **封装（Encapsulation）**：发送时，数据从上到下逐层添加头部（和尾部）
> 2. **解封装（Decapsulation）**：接收时，数据从下到上逐层去除头部（和尾部）
> 3. **路由器角色**：仅处理到网络层，进行路由转发决策
> 4. **端到端 vs 点到点**：
>   - **端到端**：运输层（主机到主机，进程到进程）
>   - **点到点**：数据链路层（相邻节点间）
> 5. **协议数据单元（PDU）**：每层处理的数据单位不同，有不同名称

> [!example] 实际通信示例流程
> 1. **发起请求**：浏览器构建HTTP请求 → 主机会层封装 → 发送到路由器
> 2. **路由转发**：路由器解封装到IP层 → 路由决策 → 重新封装转发
> 3. **服务器响应**：Web服务器解封装 → 处理请求 → 构建响应 → 反向封装返回
> 4. **主机接收**：主机解封装 → 浏览器显示网页


## 🔄 数据的双向流动
**请求方向**（主机 → Web服务器）：
```
应用层: HTTP请求报文
运输层: +TCP首部 → TCP报文段  
网络层: +IP首部 → IP数据报
数据链路层: +帧首部+帧尾部 → 以太网帧
物理层: +前导码 → 比特流 → 信号
```

**响应方向**（Web服务器 → 主机）：
```
应用层: HTTP响应报文
...（类似封装过程）...
物理层: 信号 → ... → 应用层
```

## 💡 分层思想的实际体现
> [!success] 分层方法的优势和体现
> 1. **模块独立性**：每层只需关注本层功能，如物理层只关心信号传输
> 2. **技术多样性**：下层技术变化不影响上层，如以太网、Wi-Fi等都可作为数据链路层
> 3. **问题定位**：网络故障可按层分析，快速定位问题所在层
> 4. **标准兼容**：标准化的层间接口允许不同厂商设备互操作
