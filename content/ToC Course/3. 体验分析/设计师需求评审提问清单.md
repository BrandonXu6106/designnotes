# UI/体验设计师｜需求评审提问清单
适用场景：需求评审会、PRD对齐、需求澄清，目的：提前识别风险、对齐目标、避免后期反复改稿、建立产品思维。 分为五大模块，可以直接复制会上使用，按需挑选提问。

## 一、业务与目标层（最先问，重中之重）
核心：确认大家要朝着同一个目标做事
1. 本次需求的业务背景是什么？当前存在哪些现存问题？
2. 本次改版/功能的**核心目标**是什么？（提升转化、降低流失、提升用户效率、减少客服、合规需求等）
3. 衡量本次需求是否成功的指标是什么？有无埋点规划？
4. 这个需求的优先级为什么这么高？如果排期紧张，哪些功能可以降级、删减？
5. 不做这个功能会有什么影响？有没有成本更低的替代方案？
6. 是否关联运营活动、商业化目标？有没有短期大流量预期？


## 二、用户与场景层（体验设计师核心阵地）
1. 目标用户是谁？新用户/老用户/付费用户？用户典型画像？
2. 用户会在哪些场景下使用这个功能？网络环境、设备（移动端/平板/PC）？
3. 用户完成这个功能的完整链路是什么？上游页面、下游跳转是哪里？
4. 当前用户在这条流程里，已知的痛点、投诉、数据卡点是什么？
5. 是否存在新手用户与熟手用户的体验冲突，如何兼顾？
6. 极端场景：空状态、无网络、加载失败、权限不足如何处理？


## 三、范围、规则与逻辑层（提前堵逻辑漏洞）
1. 完整的交互规则、状态分支是否全部梳理完成？
2. 是否存在多角色权限差异？不同身份看到的内容/操作是否不一样？
3. 数据来源是什么？数据为空、数据超长、数据异常如何展示？
4. 弹窗、二次确认、撤销操作、失败重试逻辑是否定义？
5. 是否存在跨端同步问题（App/小程序/H5）？多端规则是否统一？
6. 有没有隐藏分支场景PRD没有写明，需要补充？


## 四、交互、体验与设计边界
1. 现有产品组件库、通用交互范式是否需要遵守？是否允许打破现有规范？
2. 是否存在动画、过渡效果、手势交互需求？
3. 有无无障碍、深色模式、多语言适配要求？
4. 是否需要兼容低版本系统、小屏设备？
5. 功能是否存在引导需求（新手浮层、气泡引导、教学弹窗）？


## 五、研发、排期、风险与落地（避免设计做完无法落地）

1. 整体排期节点：设计截止、开发启动、提测、上线时间？
2. 开发实现成本如何？有没有技术难点、性能风险？
3. 哪些能力一期实现，哪些二期迭代？区分[[ToC Course/3. 体验分析/MVP|MVP]]完整版。
4. 接口什么时候就绪？是否存在[[ToC Course/3. 体验分析/接口延迟|接口延迟]]导致页面状态变化？
5. 测试重点场景有哪些，设计是否需要同步提供验收标准？
6. 上线后灰度策略？是否支持小流量测试观察数据？


## 六、补充兜底问题（容易遗漏）

1. 需求是否有合规要求（隐私协议、内容审核、金融/医疗特殊规范）？
2. 和其他团队模块有没有耦合，是否需要跨团队协同对齐？
3. 本次需求有没有运营配套物料、文案、弹窗话术需要同步输出？

## ✅ 两种使用方式

### 方式1：会上精简口语版（直接照着问）
> 先确认业务目标与衡量指标 → 理清目标用户和使用场景 → 核对完整流程与异常状态 → 确认组件规范与适配要求 → 对齐排期、技术限制、一期二期范围。


### 方式2：自我预审清单（评审会前自查）
开会前自己先过一遍，把有疑问点提前标记，不要等到会上临时发问。

## 💡 设计师沟通小技巧

少用质疑语气，多用对齐句式： 
❌ “PRD这里逻辑有问题” 
✅ “想跟大家对齐一下这个场景，当XX情况发生时，页面应该如何展示？”

如果你想要，我可以再输出一份 **【需求评审会后纪要模板】**，方便你记录结论、锁定共识，防止后续需求反复变更。
