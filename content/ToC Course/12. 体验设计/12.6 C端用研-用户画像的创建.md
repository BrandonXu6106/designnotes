**体验设计**：==以用户为中心==设计，先确定目标用户==是谁==，以及有什么==特点==
- 确定调研对象(是谁) → 调研用户 → 解决问题


## 1. 画像的作用
用于概括目标用户群体特征的==虚拟人物==，是体验设计前期==认识==目标用户的主要方法

**目的**：
- 归纳总结→形成认知
	- 一个群体的每个成员都有各自的特点和差异，将它们合并成一个单体时只==关注共性忽视差异==
	  ![202607251635982.png|424](https://int-1330323257.cos.ap-guangzhou.myqcloud.com//obsidian/pic/202607251635982.png)

- 生成代号→促进团队内信息传递
	- 作为单体——有各自的姓名
	- 作为代号——便于称呼和记忆，在团队内部协作时远胜过一个模糊的群体
	  ![202607251635241.png|455](https://int-1330323257.cos.ap-guangzhou.myqcloud.com//obsidian/pic/202607251635241.png)
- 形成用研维度→特定类型用户的分析和总结
	- 用研往往需要根据用户的类型开展
	- 不同用户群，对应不同的分析和总结
	  ![202607251645035.png|397](https://int-1330323257.cos.ap-guangzhou.myqcloud.com//obsidian/pic/202607251645035.png)


## 2. 创建的流程
>前置思考 → 类型探索 → 制定属性 → 展开调研 → 完成输出

### 2.1. 前置思考
了解==项目==的基本信息和==业务==内容
了解制定用户画像的==目的和动机==
确定后续调研的==方式==和==时间==节点

### 2.2. 用户类型的探索
任何产品立项之初都会指定==大致的目标用户==
需要先把主要目标用户群体确定出来再做调研
![202607251653643.png|360](https://int-1330323257.cos.ap-guangzhou.myqcloud.com//obsidian/pic/202607251653643.png)

> [!tip] 目标用户和用户画像的关系
> 目标用户：宏观方向——某类型
> 用户画像：信息补充——收入、教育水平...


### 2.3. 属性制定
建立用户画像需要制定关注的属性类型
通过填充这些属性的信息，实现对用户的总结
- 生理属性、外在属性、内在属性...

> [!example] 案例1——两步走APP(出行)
> - **生理属性**：性别、年龄、体重、BMI、体能水平
> - **外在属性**：所在地、职业、学历、收入、婚配、生育
> - **内在属性**：参与主要原因、出行人数选择、出行规划方式、喜爱运动品牌、运动装备价格、其它运动爱好

> [!example] 案例2——95分APP(二手购物)
> - **生理属性**：性别、年龄、身高、体重、脚码
> - **外在属性**：所在地、职业、学历、可支配收入、收入来源、婚配、生育
> - **内在属性**：二手购买类型、二手商品态度、转手物品频率、对潮流的关注、其它平台使用


>**TIPS：**
>- ==不同产品==，需要总结的用户==属性完全不同==
>- 哪些属性是==有价值==的，需要设计师自己判断
>- ⭐想不出有什么用的属性，就是没用，==不要凑数==


### 2.4. 用户调研
展开==具体调研==，完成对不同用户类型的==属性填充==
- **三种方式**：
	- **实践调研**：展开具体的问卷调查或访谈
	- **数据分析**：通过数据总结部分用户特性
	- **逻辑分析**：根据以往经验用逻辑推导结果


>**TIPS**：数据
>- 认识用户时，==数据并不是必然存==在且完整的
>	- ==敏感信息==无法收集
>	- 当前没有数据==积累==
>	- 数据的==准确性==存疑


### 2.5. 结果输出
将所有信息内容==填充==后，以合理的==图文==形式进行==输出／归档==
![202607251726182.png|396](https://int-1330323257.cos.ap-guangzhou.myqcloud.com//obsidian/pic/202607251726182.png)

## 3. 阶段性整理方法
用户画像在产品的==不同阶段==有不同的整理形式

|          | 初期阶段 | 发展阶段 | 成熟阶段 |
| -------- | ---- | ---- | ---- |
| **用户类型** | 主观决定 | 数据验证 | 数据细分 |
| **用户属性** | 经验推导 | 用研完善 | 数据完善 |

## 4. 总结
> [!summary] 
> - 设计师需要掌握基础的逻辑画像分析能力
> - 多数项目没有足够的时间和数据来建立画像
