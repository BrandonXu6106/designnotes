先一句话： **监听 = 持续盯着某一个数据，只要它一变，立刻自动执行一套动作。**

## 1. 本质对比（结合你刚学的变量、文本）

普通触发模式（按钮点击、手势、载入）：
> 需要用户主动操作，才运行交互。


监听模式：
> 不需要用户点任何东西；**变量一旦发生变化，自动触发响应**。


生活类比
- 普通交互：有人敲门你才开门（主动事件触发）
- 监听：监控摄像头一直盯着门口，有人出现立刻报警（持续观察，自动响应）



---

## 2. ProtoPie 里监听在哪里？
菜单名称：**Watch（侦听）** 添加方式： `添加响应 → Watch（侦听） → 选择要监听的【变量】`
> ⚠️ 重点：**Watch 只能监听【变量】，不能直接监听文本图层！** 再次印证前面结论：图层只是显示，不适合作为数据源；监听机制设计就是围绕变量。


## 3. 基础工作流程
1. 创建变量 `score`（数字）
2. 添加【侦听 Watch】→ 目标：`score`
3. 在侦听里面放一堆动作：文本修改、动画、震动、跳转、赋值……
4. 任何地方只要执行：`score = xxx`（赋值改变变量） 👉 **侦听自动执行，不用额外绑定交互！**


## 4. 实战例子：计数器搭配监听（感受优势）
常规写法（不用监听） 按钮点击： ① 赋值 `count = count +1` ② 文本 = `count`
**缺点：每一次修改变量，都要手动带上【修改文本】动作；多处修改count时很容易漏写，界面不更新。**
✅ 使用侦听优化写法（规范推荐）
1. 变量 count = 0
2. 新建【侦听 count】 内部只放一条动作：文本图层显示 `count`
3. 按钮点击只需要：赋值 `count = count +1`

逻辑： 只要 count 通过赋值发生改变 → Watch 自动刷新文字 以后任何地方修改count（弹窗、其他按钮、计时器），界面**自动同步更新**，不用重复添加文本动作。

## 5. 监听常见实用场景
1. **数据多处同步展示** 购物数量、分数、进度条，一个变量控制多个文本/图形，一改全刷新
2. **条件自动触发** 监听 `hp`，当 hp ≤0 → 侦听内判断，自动弹出游戏结束弹窗

```
if(hp <= 0, 跳转失败页面, "")
```
3. **进度联动动画** 变量 progress 由计时器持续赋值，侦听驱动进度条宽度变化
4. **跨组件数据同步** 组件内外共用变量，变量一变，组件内UI自动刷新


## 6. 关键特性 & 大坑（一定要记）
### ① 只有【赋值动作】才会触发侦听
仅仅在**文本表达式读取变量、动画读取变量**，不会触发！
> `文本 = count` 只是读取count，count本身没变 → Watch不执行 `count = count +1` 赋值改变变量 → Watch触发


### ② 不要在侦听内部无限循环赋值！
危险写法： 侦听count → 内部写赋值 `count = count + 1` 结果：变量一变→触发侦听→再次修改变量→再次触发……**死循环卡死原型**

### ③ Watch 拿得到新旧值
表达式内置两个关键字：
- `newValue`：变量**改变之后**的新数值
- `oldValue`：改变之前旧数值 示例：

```
newValue > oldValue
```
用来判断数字是增加还是减少，实现加分动画/减分不同效果。

### ④ 无法监听图层 text
想监控文本图层文字变化，原生做不到。 解决方案：图层文本变化时同步赋值给变量，转而监听这个变量。

## 7. 最简区分记忆
- **点击/载入/计时器**：主动事件 → 手动执行动作
- **Watch 侦听**：被动监控变量 → 变量变动，自动执行


## 8. 延伸结合你之前的疑问
你之前问：能不能只用文本图层做计数器？ 现在就能理解底层设计思路： ProtoPie整套高级机制（侦听、跨页面传递、持久数据）**全部建立在变量体系上**。 图层文本只是视图，不参与数据驱动； 想要自动联动、监听、批量同步UI，必须依托变量。
